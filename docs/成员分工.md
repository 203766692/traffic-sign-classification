# 🤝 交通标志分类项目 - 重新分工与协作指南

## 👥 一、 团队角色与职责划分

经过调整，为了让每个人的效率最大化（特别是考虑到部分成员没有本地 GPU 训练环境），我们重新划分分工如下：

### 👨‍💻 成员 A（组长）：核心代码开发与架构维护
- **工作环境**：普通电脑（无 GPU），本地配置 CPU 版 PyTorch。
- **核心职责**：负责编写整个项目的骨架、数据加载、模型构建、训练引擎代码。
- **主要产出**：提供完整的、可运行的代码；修复训练过程中出现的代码 Bug；实现优化逻辑（如学习率衰减、最佳模型保存）。
- **不负责**：大规模的模型训练。

### 🚀 成员 B：模型训练与实验评估执行
- **工作环境**：拥有 GPU 的训练机。
- **核心职责**：负责把成员 A 写好的代码拉取到训练机上；配置训练环境；下载 GTSRB 数据集；执行训练和微调。
- **主要产出**：跑出实验日志（Logs）、保存 `best_model.pth` 权重、收集并记录 ResNet18 和 MobileNetV3 的各项评估指标（Accuracy、F1-score 等）。
- **关键点**：遇到代码报错，**不要自己乱改代码**，截图或复制报错信息发给成员 A 修复。

### 📝 成员 C：文书撰写与结果可视化
- **工作环境**：任意电脑。
- **核心职责**：负责《多媒体技术》课程实验报告、PPT 的制作，以及项目文档的维护。
- **主要产出**：根据成员 A 的代码逻辑和成员 B 跑出的日志结果，画出 Loss/Acc 曲线，撰写算法说明、结果对比分析（微调 vs 线性探测）、整理项目文档。
- **不负责**：不需要跑代码，只需向 B 索要日志数据和图表素材。

## 🔄 二、 核心工作流（三方交接闭环）

为了保证实验顺利推进，我们严格按以下流程交接：

1. **A 开发代码**：A 在本地写好代码并完成基础测试（只跑 1 个 batch 确保不报错），推送到 GitHub 的 `main` 分支。
2. **B 拉取并训练**：B 在 GPU 机器上执行 `git pull origin main` 更新代码。跑通训练后，记录下超参数（如学习率、batch_size）和最终的实验结果。
3. **B 反馈与提交**：B 将跑出的训练日志（`experiments/logs/`）和模型权重（`experiments/checkpoints/best_model.pth`）打包，或者直接把测试集上的最佳准确率数据发给 A 和 C。如果代码报错，截图发给 A。
4. **C 撰写报告**：C 收集 B 的数据，配合 A 的代码讲解，撰写实验报告。C 如果需要补充特定指标，可以告诉 A，A 写工具函数，B 重新跑一下把数据给 C。

## 🚫 三、 Git 协作规范（关键铁律）

⚠️ **铁律：绝对不要直接在 `main` 分支上写代码和提交！`main` 分支必须永远保持稳定可运行的状态。**

### 给 A（组长）的规范：
- 每次开发前：`git checkout main` -> `git pull origin main`
- 建新分支：`git checkout -b feature/xxx-A` （如 `feature/core-code-A`）
- 提交规范：`feat: 实现数据加载逻辑`，写完后提 PR，等 B 或 C 审查通过后合并。

### 给 B（训练机）的规范：
- **每次开始训练前，必须先拉取最新代码**：`git pull origin main`。
- 如果你为了适配 GPU 机器修改了 `configs/config.yaml`（比如把 `batch_size` 改大了），**请不要把这行修改提交到 `main`**，否则会影响其他人。建议直接建一个 `configs/config_gpu.yaml` 单独保存训练配置。
- **千万不要**把 `experiments/` 里生成的权重文件（`.pth`）用 `git add` 传到 GitHub，太大了！

### 给 C（文书）的规范：
- C 如果需要修改 `README.md` 或添加文档（如 `docs/report.md`），请切出 `docs/xxx-C` 分支，改完后提 PR。

## 💡 五、 避坑与环境说明

1. **A 的本地测试**：A 因为没有 GPU，如果跑 `python scripts/train.py` 会非常慢。A 只需要通过构造虚拟张量（Mock Data）或者仅跑 1-2 个 batch，确保代码逻辑跑通、不报错即可。
2. **数据防泄露**：所有人的本地目录中，`data/` 和 `experiments/` 都必须在 `.gitignore` 里，**绝不能**被推到远端仓库。
3. **报错处理**：B 在训练机上报错，直接把终端里的 `Traceback` 复制发给 A 或者发到群里，A 负责定位修改。
