# 🤝 交通标志分类项目 - 团队协作与角色分工指南

## 👥 一、 团队角色与核心职责（面向最终交付）

为了高效完成《多媒体技术》课程项目的最终交付，团队按照“**代码与实验 -> 汇报展示 -> 实验报告**”的闭环进行职责划分。

### 👨‍💻 成员 A（组长）：代码架构与实验主力
- **工作职责**：负责项目整体架构设计、核心代码编写（数据加载、模型构建、训练引擎）、以及主力实验的执行与数据记录。
- **核心产出**：提供完整的可运行代码库；主导完成 ResNet18 线性探测、MobileNetV3 线性探测、ResNet18 微调实验，确保项目核心指标（如 ResNet18 微调准确率破 99%）达成；负责解决全流程中的技术 Bug。
- **交付任务**：向 B 和 C 提供完整的实验数据（Logs、图表素材、准确率指标）和代码逻辑讲解，作为 PPT 和报告撰写的坚实支撑。

### 🚀 成员 B：实验补充与展示统筹（PPT + 汇报）
- **工作职责**：负责补充特定实验、核对数据，并主导课程汇报的展示材料制作与现场宣讲。
- **核心产出**：完成 MobileNetV3 微调实验记录与归档；基于 A 提供的全套实验数据和 C 撰写的报告核心结论，制作高质量、逻辑清晰的汇报 PPT。
- **交付任务**：负责课堂汇报的讲演；配合 C 完成报告中实验可视化图表（Loss/Acc 曲线等）的美化与核对。

### 📝 成员 C：实验报告撰写与文档统筹
- **工作职责**：负责《多媒体技术》课程实验报告的整体撰写、排版与学术化润色。
- **核心产出**：严格对照课程报告模板，完成摘要、引言、算法原理、实验分析（微调 vs 线性探测对比、不同架构对比）、结论等章节的撰写。
- **交付任务**：向 A 索取代码逻辑说明，向 B 索要实验结果和图表素材。确保报告的格式合规（字体、字号、图表编号等），并在最终提交前完成查重和格式终审。

## 🔄 二、 结课阶段核心工作流（三方交接闭环）

当前项目已完成全部代码开发和实验跑通，接下来的重心是**材料沉淀与汇报**：

1. **A 整理资产并交付**：A 将最终版的代码结构、四大实验的最终指标（Accuracy、F1-score）、TensorBoard 导出的 Loss/Acc 原始图表打包发给 C 和 B，并确保 `README.md` 等文档是最新的。
2. **C 主导报告撰写**：C 根据 A 的代码原理和实验数据，按照报告模板撰写正文。遇到需要补充说明的算法细节，及时向 A 确认。
3. **B 主导 PPT 与汇报**：B 提取报告中的核心亮点（如“基于迁移学习的双架构对比”、“四大实验全部闭环”），制作 PPT。B 与 C 核对 PPT 中的数据，确保口径一致。
4. **交叉审查与终稿**：A 负责审查报告和 PPT 中的技术描述是否准确；B 进行试讲（可给 A、C 预演）；C 负责最后的格式统一和文档提交。

## 🚫 三、 Git 协作规范（关键铁律）

⚠️ **铁律：绝对不要直接在 `main` 分支上写代码和提交！`main` 分支必须永远保持稳定可运行的状态。**

- **A（技术兜底）**：继续维护 `main` 分支，审查 B 和 C 提交的文档/代码 PR。如果 B 或 C 在撰写文档时需要修改代码仓库中的 Markdown 文件，A 负责协助合并。
- **B & C（文档与素材协作）**：由于后续主要是文档工作，建议 B 和 C 建立 `docs/report-C` 和 `docs/ppt-B` 分支，或者直接在本地/共享文档中协作。如果需要更新仓库的 `README.md` 或添加报告源文件，请提 PR 由 A 审查合并。
- **防污染**：务必确保不要将本地大文件（如 `.pptx` 或 `.docx` 的中间生成超大素材）、数据集、权重文件 (`*.pth`) `git add` 到仓库中。
